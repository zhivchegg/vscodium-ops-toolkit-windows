# tmux

Терминальный мультиплексор: несколько окон и панелей в одной сессии. Незаменим при длительных операциях и мониторинге.

## Что проверить при инциденте

1. Нужно ли следить за несколькими логами одновременно?
2. Выполняется ли длительная команда, которую нельзя прерывать?
3. Нужно ли сохранить терминальную сессию при отключении?

## Сессии

```bash
# Создать новую сессию
tmux new -s logs

# Создать сессию без подключения
tmux new -d -s logs

# Подключиться к существующей
tmux attach -t logs

# Переименовать сессию
# Внутри tmux: Ctrl+B, затем $

# Список сессий
tmux ls

# Отключиться от сессии (не закрывая её)
# Нажать Ctrl+B, затем D

# Убить сессию
tmux kill-session -t logs

# Убить все сессии
tmux kill-server
```

## Окна

```bash
# Создать окно: Ctrl+B, затем C
# Переключиться: Ctrl+B, затем N или P
# Переименовать: Ctrl+B, затем ,
# Закрыть: Ctrl+B, затем &
# Список окон: Ctrl+B, затем W
```

## Панели

```bash
# Разделить по вертикали: Ctrl+B, затем %
# Разделить по горизонтали: Ctrl+B, затем "
# Перемещаться: Ctrl+B, затем стрелка
# Увеличить/уменьшить: Ctrl+B, затем Ctrl+стрелка
# Закрыть: Ctrl+B, затем X или ввести exit
# Синхронизировать ввод во все панели: Ctrl+B, затем :
# затем ввести setw synchronize-panes
```

## Сценарий мониторинга инцидента

```bash
tmux new -s incident

# Панель 1: логи приложения
tail -f /var/log/app.log | err

# Панель 2: логи nginx
tail -f /var/log/nginx/access.log

# Панель 3: метрики системы
watch -n 2 'df -h && echo --- && free -m'
```

## Запуск скрипта в фоновой сессии

```bash
tmux new -d -s long-job 'bash /opt/scripts/backup.sh'

# Позже подключиться и посмотреть статус
tmux attach -t long-job
```

## Восстановление после обрыва связи

```bash
# Подключиться к существующей сессии
tmux attach -t logs

# Или к последней активной
tmux attach

# Отключить другого клиента и подключиться самому
tmux attach -d -t logs
```

## Базовая настройка ~/.tmux.conf

```bash
# Сменить префикс на Ctrl+A
set -g prefix C-a
unbind C-b
bind C-a send-prefix

# Включить мышь
set -g mouse on

# Увеличить историю прокрутки
set -g history-limit 10000
```

## Подводные камни

- tmux сессии живут, пока запущен сервер — при перезагрузке машины они пропадают.
- Копирование мышью в tmux может конфликтовать с прокруткой — зажмите Shift для выделения.
- Префикс по умолчанию `Ctrl+B` — если он конфликтует, можно изменить в `~/.tmux.conf`.
- `setw synchronize-panes` удобен для выполнения одной команды на нескольких серверах, но опасен на production.
