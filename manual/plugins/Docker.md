# Docker

Плагин Docker добавляет проводник контейнеров, образов и сетей, а также помогает писать Dockerfile и docker-compose.yml.

## Что проверить при инциденте

1. Запущен ли Docker Engine на машине?
2. Видны ли контейнеры в боковой панели Docker?
3. Есть ли ошибки в логах контейнера?
4. Не закончилось ли место на диске образами?

## Панель Docker

Открыть: `Ctrl+Shift+P` → `Docker: Focus on Containers View`.

В проводнике доступно:
- запуск/остановка/перезапуск контейнеров
- просмотр логов
- выполнение команд внутри контейнера
- удаление образов и томов

## Быстрые проверки в терминале

```bash
# Список запущенных контейнеров
docker ps

# Все контейнеры, включая остановленные
docker ps -a

# Логи контейнера
docker logs <container>

# Логи в реальном времени
docker logs -f <container> --tail 100

# Выполнить команду внутри контейнера
docker exec -it <container> sh

# Использование ресурсов
docker stats --no-stream
```

## Диагностика зависшего контейнера

```bash
# Найти контейнер по имени
CONTAINER=$(docker ps -q -f name=app)

# Посмотреть последние ошибки
docker logs "$CONTAINER" 2>&1 | tail -n 50 | err

# Проверить состояние процессов
docker top "$CONTAINER"

# Инспектировать перезапуски и статус
docker inspect --format='{{.State.Status}} {{.State.RestartCount}} {{.State.Error}}' "$CONTAINER"
```

## Очистка диска

```bash
# Удалить остановленные контейнеры
docker container prune -f

# Удалить неиспользуемые образы
docker image prune -a -f

# Удалить неиспользуемые тома (осторожно!)
docker volume prune -f

# Общий сборщик мусора
docker system prune -a --volumes -f
```

> **Внимание:** `docker system prune` удаляет всё неиспользуемое. В продакшене запускайте только после проверки списка затронутых объектов.

## Работа с docker-compose

```bash
# Поднять стек
docker-compose up -d

# Пересобрать и поднять
docker-compose up -d --build

# Масштабировать сервис
docker-compose up -d --scale app=3

# Логи всего стека
docker-compose logs -f --tail 100
```

## Подводные камни

- Время в логах контейнера совпадает с хостом только при правильном монтировании `/etc/localtime`.
- `latest` тег не гарантирует актуальность образа — лучше использовать конкретные версии.
- Если контейнер падает сразу после старта, смотрите `docker logs` до того, как успеет удалиться.
