# Bash IDE

Плагин Bash IDE добавляет в VSCodium автодополнение, переход к определениям и интеграцию с shellcheck для bash-скриптов.

## Что проверить при инциденте

1. Открыт ли файл с расширением `.sh` или шебангом `#!/bin/bash`?
2. Работает ли shellcheck? Ошибки видны во вкладке **Problems** (`Ctrl+Shift+M`).
3. Правильно ли определён интерпретатор в настройках?

## Навигация и автодополнение

- `Ctrl+Click` на функцию — переход к определению.
- `Ctrl+Shift+O` — список функций в файле.
- Автодополнение встроенных команд bash и переменных.

## Запуск скриптов

В терминале VSCodium (MSYS2 Bash):

```bash
bash script.sh
bash -x script.sh          # отладка: печать каждой выполненной команды
bash -n script.sh          # проверка синтаксиса без выполнения
```

## Интеграция shellcheck

Ошибки и предупреждения отображаются во вкладке Problems. Пример типовых проблем:

| Код | Описание | Исправление |
|---|---|---|
| SC2046 | Word splitting при `$(...)` | Заключить в кавычки `"$(...)"` |
| SC2086 | Незащищённые переменные | `"$var"` вместо `$var` |
| SC2002 | Лишний `cat` | Использовать redirection `< file` |
| SC1091 | Не удалось проверить sourced-файл | Добавить `# shellcheck source=path` |

Чтобы отключить предупреждение в конкретной строке:

```bash
# shellcheck disable=SC2086
rm -rf $path
```

## Отладка скриптов

```bash
# Вывести каждую команду перед выполнением
set -x
# ... ваш код ...
set +x

# Остановиться при ошибке
set -e

# Остановиться при использовании незаданной переменной
set -u
```

## Практический пример: диагностика падения сервиса

```bash
#!/bin/bash
set -euo pipefail

SERVICE="nginx"
LOG="/var/log/app.log"

# Проверка статуса
if ! systemctl is-active --quiet "$SERVICE"; then
    echo "ERROR: $SERVICE не запущен"
    echo "Последние строки лога:"
    tail -n 20 "$LOG" | err
    exit 1
fi

echo "OK: $SERVICE работает"
```

## Полезные сочетания

- `F5` — запуск текущего скрипта (если настроен launch.json).
- `Ctrl+Shift+M` — панель Problems.
- `Ctrl+\`` — открыть/закрыть терминал.
